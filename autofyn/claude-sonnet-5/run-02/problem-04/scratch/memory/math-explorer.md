ALWAYS: for geometric "cut a triangle" game problems, first derive the exact angle-triple formulas for both children of a cevian cut and look for a summation identity between them (e.g. the two "new" angles at the cut point sum to the original angle-sum, 180°) — it is usually the single fact that both proves impossibility (invariant argument) and reveals which target values are "universally" forceable in one move (round 2, imo-2026-04).
NEVER: assume Shan-Yu (the adversary who picks initial data) can be blocked by a genericity/transcendence argument when the other player's per-move parameter is a freely chosen real number revealed after seeing the state — the mover can always compute an exact response from the actual revealed value, so genericity defenses fail; only genuine closed invariants (a set of states provably preserved under at least one of the two branches) work (round 2, imo-2026-04).
ALWAYS: distinguish two opposite uses of "genericity" in mover/adversary games — (1) it does NOT block a single move's local double-hit condition (the mover sees the exact revealed number and can always solve for its own free parameter, so a defender cannot dodge one specific equation), but (2) it DOES work at the level of the WHOLE strategy tree when the adversary picks the initial data BEFORE play and the tree is only countable: each node imposes finitely many "coincidence" (non-identity) polynomial conditions on the adversary's initial parameters, a countable union of these is a proper subset of the parameter space, so the adversary can pick initial data avoiding all of them, forcing every node's success to rely only on true algebraic identities, not coincidences. This second form is a legitimate necessity-direction tool for games where one player commits data up front (round 2, imo-2026-04).
ALWAYS: for "opponent forced into a unique escape branch" games, look for a generalized "transfer" move: if one child of a split hits the target directly, the adversary is FORCED into the other (non-losing) child even without a genuine invariant — this deterministic single-child transition is often far more powerful than symmetric double-hit lemmas and can be chained/recursed to build much larger forceable families than the "obvious" special-value family found first (round 2, imo-2026-04).
NEVER: trust a restricted-move-family AND-OR game search's "False" (not-found) result as evidence of impossibility — it only proves the tested move family + depth bound can't reach it; a "True" hit on a seemingly "uglier" value (e.g. 180/7°) than a "nicer" one that returned False (e.g. 25°) in the same search is a sign the move family is incomplete or the depth cutoff bit, not that the nicer value is truly unreachable — report both as open, not as a proven dichotomy (round 2, imo-2026-04).
ALWAYS: when a "genericity/closure" necessity proof is refuted by omitting one move-generator, check whether the omitted generator is *already* covered by an existing "no cancellation" propagation lemma before redoing the algebra from scratch — often only the closure's combinatorial description (which values are reachable) needs fixing, not the underlying algebraic-independence argument (round 4, imo-2026-04).
ALWAYS: when scouting a closure-operator repair, actually run a symbolic/numeric sweep (represent reachable values as A+B*theta over many random operation sequences, exact Fraction arithmetic) before declaring a conjectured closed form plausible or doomed — a few thousand random trials with zero counterexamples is much stronger scouting evidence than hand-checking 2-3 cases (round 4, imo-2026-04).
