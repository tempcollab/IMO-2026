## imo-2026-03 — lens: direct attack on Claim U(m), Case 3 (middle case)

### Setup recap
U(m): A = (a1≥...≥am≥0), T=ΣA, β=T/(2^m−1). Need m−1 cuts (Xiang's move-process: Bisect/Match/FreeRetire) driving Δ(final) ≤ β. Cases 1 (a1≥2^{m−1}β, via Bisect) and 2 (a2≥2^{m−2}β, a1>a2, via Match) are proved. Case 3 (a1<2^{m−1}β AND a2<2^{m−2}β, m≥3) plus the a1=a2 tie sub-case of Case 2 are open. This is the ONLY remaining gap in the whole problem (lower bound fully certified via `ladder-resists`).

### New finding: a strictly stronger move closes a large chunk of Case 3 directly (no induction needed)

I numerically optimized Δ over ALL cut allocations (not just the Bisect/Match/FreeRetire vocabulary) for random Case-3 instances at m=4 using Nelder–Mead over cut positions (script in scratch, not committed). The optimizer repeatedly finds a pattern the existing approach file does not name: **cut a1 into (m−1) sub-pieces that each match one of a2,...,am exactly, except one sub-piece which absorbs the residual.** Concretely: set x_i = a_i for i=3,...,m (using m−2 cuts on a1 alone) and x_2 = a1 − (a3+...+am). Pairing x_i against a_i gives exact ties (Δ-contribution 0) for i=3..m, and the single remaining pair (x_2, a2) has gap exactly |a1 − (a2+a3+...+am)| = |2a1 − T| (since a2+...+am = T−a1). **This uses only m−2 cuts** (one spare), leaving am (or another small leftover) to be bisected for free if needed.

*Algebraic check (this is a proof-shaped fact, not just numerics):* 2a1 − T < β ⟺ a1 < (T+β)/2 = T·2^{m−1}/(2^m−1) = 2^{m−1}β — **exactly the Case-1 threshold**, i.e. exactly the boundary already defining "not Case 1." So: **whenever a1 < 2^{m−1}β (the Case 3/Case 2 regime) AND a1 ≥ a3+a4+...+am (a feasibility condition, so that x2 = a1−(a3+...+am) ≥ 0), this single explicit construction gives Δ = |2a1−T| ≤ β with only m−2 cuts, no induction, no case-2/case-3 split needed.**

I verified numerically (Dirichlet-random middle-case sampling) that the feasibility condition a1 ≥ a3+...+am holds for **100% of Case-3 instances at m=3, ~85% at m=4, ~61% at m=5, ~40% at m=6** — i.e. it degrades for larger m but is a strong partial closer, especially valuable since m=3 (the base of the open induction) is **fully closed by this construction alone** (no Case-3 instances fail feasibility at m=3).

### Where this construction is NOT enough (larger m, "spread out" partitions)
When a1 < a3+...+am (fails feasibility — happens for near-uniform-ish partitions among the smaller pieces, worse for larger m), the naive "give a1's mass to a2,...,am in fixed rank order" over-commits (x2 would go negative). The fix needs a **choice of which subset of {a2,...,am} to match a1 against** (not necessarily the top m−2 by rank) — a bin-covering/greedy-assignment flavor: pick a subset J ⊆ {2,...,m} with Σ_{j∈J} a_j ≤ a1 as large as possible (ideally close to a1), match a1's mass onto exactly those, and recurse on the leftover residual set (unmatched a_j's plus the small mismatch) using the remaining cut budget m−1−|J|. I did NOT solve this sub-case; it is the actual remaining content of Case 3. Numerically (m=4,5,6) the true optimal Δ stays well under β even in the infeasible sub-case (optimizer always finds ~β/5 to β/50 in samples tried), so U(m) itself is not in danger — only the *proof mechanism* for this residual slice is missing.

### Distinct openings (ranked by how directly they attack Case 3)

1. **"Multi-match the top piece" construction (new, this round).** As above: generalizes Match from a 2-piece move to an (m−1)-piece move (a1 vs. all of a2..am at once). Closes Case 3 whenever a1 ≥ Σ_{i≥3} a_i, using only m−2 cuts. This is a genuinely different top-level move from Bisect/Match/FreeRetire — it should probably be added to the move vocabulary as **MultiMatch**, and the induction restructured as: if a1 ≥ a3+...+am, done directly (no recursion); else recurse via a greedy covering-subset choice (see below).

2. **Greedy covering-subset MultiMatch (new, NOT yet solved — the actual open gap).** When a1 < a3+...+am: choose the subset J of {a2,...,am} of SMALLEST pieces first (greedy fill, bin-covering style) such that Σ_{j∈J} a_j is the largest sum ≤ a1 (or handle the crossing element specially, splitting it too). Match a1 across all of J with |J| cuts (one cut fewer than |J| targets, since MultiMatch of a1 into |J| pieces takes |J|−1 cuts) — wait, actually splitting a1 into |J| pieces to match |J| targets needs |J|−1 cuts (matches earlier: m−1 targets needed m−2 cuts). Recurse on the residual: the uncovered elements of {a2,...,am}\J plus whatever slack a1 has left (0 if exactly covered). This is a genuinely promising but unworked line — flag to outliner as the primary Case-3 candidate.

3. **Tail-min invariant** Δ ≤ min_{1≤j≤m} T_j/(2^j−1) (T_j = sum of j smallest active pieces), already flagged in the approach file as the strengthened induction hypothesis. I did NOT independently verify this beyond the file's own claim; it's consistent with all the numerics I ran (ladder equalizes it) but is a DIFFERENT strategy from the MultiMatch idea above — worth keeping as a fallback/alternative if MultiMatch's induction gets messy, but the file's own note that "the induction closes for min attained at j≤m−1 via Bisect, reduces j=m case to Cases 1–2 plus the same middle case" suggests this invariant alone circles back to the same wall (doesn't obviously handle the a1<Σ_{i≥3}a_i sub-case any better than raw Case 3). Lower priority than opening 2.

4. **Direct/global reformulation bypassing the move-process altogether.** The move-process (Bisect/Match/FreeRetire, now +MultiMatch) is a *proof technique* chosen by the builders, not forced by the problem — U(m) itself only asks for existence of SOME m−1-cut reply achieving Δ≤β. An alternative framing: use the **tie-structure catalog** (`lemmas/tie-structure.md`, V1–V4, certified) directly on the m-piece sub-problem — i.e., treat U(m) as its own instance of the Stackelberg game (m pieces already fixed, "Liu" doesn't get to choose them) and ask what the *finite catalog of pinned-tie replies* looks like for m=3,4,5 symbolically. This could either (a) confirm the MultiMatch pattern IS the pinned minimizer generically (in which case opening 2 is provably optimal, not just heuristically good), or (b) reveal a different pinned pattern in the residual/infeasible sub-case that the case analysis above hasn't spotted. This is a genuinely different top-level attack — worth a slot in the field since it could shortcut proving Case 3 case-by-case.
